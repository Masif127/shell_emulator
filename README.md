# Эмулятор языка оболочки ОС (Вариант №19)

## 1. Общее описание проекта
Данный проект представляет собой эмулятор командной строки UNIX-подобной операционной системы, реализованный в форме графического интерфейса пользователя (GUI)[cite: 63]. Приложение функционирует в интерактивном режиме (REPL), поддерживает ввод параметров конфигурации командной строки, последовательное пакетное исполнение команд из стартового скрипта, а также оперирует изолированной виртуальной файловой системой (VFS), развернутой непосредственно в оперативной памяти компьютера без модификации исходных данных на диске[cite: 63, 64]. Разработка ведется поэтапно с сохранением каждого этапа стандартно оформленным коммитом в публично доступном git-репозитории[cite: 6, 63].

**Спецификация варианта №19:**
- **Интерфейс:** Графический интерфейс (GUI) с обязательным отображением имени VFS в заголовке окна[cite: 63].
- **Особенности парсера:** Простой парсер, разделяющий входную строку на имя команды и аргументы по пробелам[cite: 63].
- **Источник VFS:** CSV-файл (двоичные данные кодируются в base64; поддержана структура представления вложенных элементов)[cite: 64].
- **Основные команды:** `ls`, `cd`, `tree`, `head`, `exit`[cite: 63, 64].
- **Дополнительные команды (in-memory):** `mkdir`[cite: 65].

## 2. Описание всех функций и настроек

### Графический интерфейс и REPL-цикл (Этап 1)
- **Интерактивный диалог:** Непрерывный цикл обработки команд в графическом окне (GUI)[cite: 63].
- **Заголовок окна:** Динамически отображает имя смонтированной виртуальной файловой системы[cite: 63].
- **Парсинг командной строки:** Простой парсер производит токенизацию введенной пользователем строки, разделяя имя исполняемой команды и переданные аргументы по пробельным символам[cite: 63].
- **Обработка и информирование об ошибках:** Реализована валидация пользовательского ввода с выводом сообщений о неизвестных командах и неверных аргументах без аварийного завершения программы[cite: 63].

### Модуль конфигурации (Этап 2)
- **Параметры командной строки:** Поддерживается запуск с параметрами `--vfs` (путь к физическому расположению CSV-файла VFS) и `--script` (путь к стартовому скрипту)[cite: 63, 64].
- **Отладочный вывод параметров:** При старте эмулятора в область вывода выводится отладочная информация обо всех переданных аргументах конфигурации[cite: 63].
- **Стартовый скрипт:** Последовательно выполняет команды эмулятора, пропуская ошибочные строки[cite: 64].
- **Имитация диалога:** При выполнении скрипта на экране отображается как ввод, так и вывод команд[cite: 64].
- **Обработка ошибок скрипта:** При возникновении ошибок во время исполнения стартового сценария выводится соответствующее сообщение[cite: 64].

### Виртуальная файловая система (VFS) (Этап 3)
- **Изоляция в памяти:** Все операции с каталогами и файлами осуществляются только в памяти (In-Memory VFS), распаковка или изменение данных VFS на диске запрещены[cite: 64].
- **Формат источника данных:** Источником VFS служит CSV-файл, содержащий древовидную структуру вложенных папок и файлов[cite: 64].
- **Кодирование бинарных данных:** Для двоичных данных файлов применяется кодирование base64[cite: 64].
- **Безопасность состояния:** Создание папок и модификации состояния VFS сохраняются только во внутренних структурах в памяти до момента завершения процесса[cite: 64, 65].

### Поддерживаемые команды (Этапы 1, 4, 5)
- `exit` — завершение работы эмулятора и закрытие графического окна[cite: 63].
- `ls [путь]` — вывод содержимого каталога (на Этапе 1 — заглушка с выводом своего имени и аргументов; на Этапе 4 — реальный просмотр узлов VFS)[cite: 63, 64].
- `cd [путь]` — смена текущего каталога в VFS (на Этапе 1 — заглушка с проверкой количества аргументов; на Этапе 4 — навигация по VFS)[cite: 63, 64].
- `tree [путь]` — рекурсивный вывод дерева файлов и папок виртуальной файловой системы[cite: 64].
- `head [-n N] <файл>` — вывод первых строк текстового файла из VFS[cite: 64].
- `mkdir <путь>` — создание нового каталога в виртуальной файловой системе в памяти[cite: 65].

## 3. Описание команд для сборки проекта и запуска тестов

### Системные требования
- **Интерпретатор:** Python версии 3.10 или выше.
- **Библиотеки:** Используется стандартная библиотека Python (`tkinter`, `csv`, `base64`, `unittest`), установка дополнительных пакетов не требуется.

### Запуск эмулятора в интерактивном режиме (GUI)
```bash
python -m src.gui --vfs ./vfs.csv
```

### Запуск эмулятора со стартовым скриптом (Пакетный режим)
```bash
python -m src.gui --vfs ./vfs.csv --script ./scripts/startup.txt
```

### Использование готовых скриптов автоматизации
- **Для Linux / macOS:**
  ```bash
  chmod +x run.sh
  ./run.sh
  ```
  или через `Makefile`:
  ```bash
  make run
  ```
- **Для Windows:** Запустите `run.bat` или выполните команду запуска `python -m src.gui` в терминале PowerShell/CMD.

### Запуск автоматических тестов
Для запуска набора тестов выполните:
```bash
python -m unittest discover -s tests
```
или через `Makefile`:
```bash
make test
```

## 4. Примеры использования

### Примеры работы в окне эмулятора (Этап 1)

**1. Проверка команд-заглушек:**
```bash
test_vfs$ ls
ls: команда вызвана, аргументы: []

test_vfs$ ls -la /usr/local/bin
ls: команда вызвана, аргументы: [-la /usr/local/bin]

test_vfs$ cd /home/user
cd: переход в '/home/user' (заглушка)

test_vfs$ cd
cd: переход в '~' (заглушка)
```

**2. Обработка ошибок ввода и аргументов:**
```bash
test_vfs$ cd dir1 dir2
Ошибка: cd: слишком много аргументов (ожидается не более 1)

test_vfs$ unknown_command
Ошибка: эмулятор: команда не найдена: unknown_command

test_vfs$ exit now
Ошибка: exit: команда не принимает аргументов
```

**3. Завершение работы:**
```bash
test_vfs$ exit
Выход из эмулятора...
```
*(Окно приложения закрывается).*

### Результаты прогона модульных тестов


**Реализованные тесты (`tests/test_emulator.py`):**
- `test_parse_input_simple` — проверка разбиения строки на команду и один аргумент.
- `test_parse_input_multiple_arguments` — проверка разделения команды и нескольких аргументов по пробелам.
- `test_parse_input_empty` — обработка пустой строки ввода.
- `test_ls_stub` — вызов команды-заглушки `ls` и корректность отображения переданных параметров[cite: 63].
- `test_cd_stub_valid` — вызов команды-заглушки `cd` с корректным путем[cite: 63].
- `test_cd_stub_too_many_arguments` — проверка вывода ошибки при передаче избыточных аргументов в `cd`[cite: 63].
- `test_exit_command` — проверка корректной установки флага завершения работы[cite: 63].
- `test_exit_command_with_args` — проверка ошибки команды `exit` при передаче аргументов[cite: 63].
- `test_unknown_command` — проверка вывода сообщения об ошибке для неизвестной команды[cite: 63].
